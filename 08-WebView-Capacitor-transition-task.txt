ЗАДАНИЕ 8. ПЕРЕХОД «СИМВОЛОВ» НА ОБЩИЙ WEB-КЛИЕНТ И CAPACITOR

Цель: завершить переход от Kotlin UI к одному web-интерфейсу для браузера и Android. Реализовать, собрать и проверить результат; одного плана или переименования прототипа недостаточно. Основной сервер остаётся API v3 / PostgreSQL. Старые данные web v2 не импортировать.

Контекст и исходники
- Репозиторий C:\repos\EVS\symbols. Рабочее дерево содержит незакоммиченные изменения предыдущих этапов: сохранить их, не откатывать и не включать посторонние исправления.
- WebClient/ — проверенный локальный прототип; обязательный исходный анализ WebClient/README.md и src/. dist/next.mjs — UI-эталон; поведение сервера и актуальный баланс — Server/ и contracts/.
- Client/ — рабочий Kotlin-клиент, источник формата сохранённых аккаунтов, журнала и функций v3. Сохранить его как возможность возврата до приёмки, не удалять аккаунты и ключи.
- Предыдущий выданный QA APK: Client/artifacts/delivery/symbols-prod-qa-web-ui-20261007.apk. Извлечь фактические package/versionCode/cert и сверить с Client/release/web-ui-qa-artifact.json. Не выдумывать подпись владельца.
- VDS 135.106.172.96, API https://symbols-api.votarumshee.com, контакт votarumshee@gmail.com. Проектируемый web origin https://symbols.votarumshee.com. Это настройка для подготовки; DNS и live deployment в данном задании не менять. Производственные записи/матчи для тестов не создавать.
- Локальный стенд предыдущего этапа: API 127.0.0.1:8080, PostgreSQL 127.0.0.1:5457 / symbols_ui_test; проверить его состояние перед использованием. Разрешены отдельные локальные тестовые базы/процессы.
- SDK/JDK/Gradle в Client/.tools. Эмуляторы API 36 emulator-5556 и API 26 emulator-5554. API 26 образ не содержит WebView: исправить окружение, если разумно, либо явно оставить внешнюю проверку; не объявлять его проверенным по minSdk.

Порядок работы
1. Аудит текущих реализаций и матрица переноса; назначить владельцев файлов при использовании помощников.
2. Общий source-каталог и завершение web UI/API v3.
3. Устойчивый браузерный вход, native-хранилище и миграция Kotlin.
4. Надёжность команд и lifecycle, полная функциональная проверка.
5. Release-подобная Android QA сборка, iOS-основа, CI/CD и инструкции.
6. Собственные доказательства по критериям ниже; передать root точные команды и пути для независимой приёмки. Найденные дефекты исправлять до сдачи.

Обязательная реализация
A01. Один основной web UI. Перенести необходимые графику, стили и доменные display-модули из исторического dist/ в поддерживаемый source-каталог WebClient/. Обычная сборка не должна зависеть от старого web v2 renderer/server. Сохранить оригинальные вид и tap→cell→direction, два поля, полку, модальные окна, эффекты. Нативная оболочка использует упакованные ресурсы; production server.url/удалённый JS и небезопасные URL запрещены. Удалить неиспользуемые promo/instant/legacy-import обработчики.

A02. Постоянный вход в браузере. Реализовать production-пригодный same-origin путь (Server или отдельный BFF) с HttpOnly, Secure, подходящим SameSite cookie и явной защитой CSRF/Origin для изменяющих запросов. Bearer-токен недоступен JS, localStorage/sessionStorage/IndexedDB и не возвращается в web JSON. Native Bearer API должен остаться совместимым. Вход сохраняется после нового browser context с сохранёнными cookies/закрытия браузера. Регистрация, восстановление, logout, отзыв/истечение и удаление аккаунта корректно очищают локальные данные и подписки. Если несколько браузерных аккаунтов нельзя безопасно поддержать выбранной схемой, реализовать переключение через серверные cookie-сессии, а не хранить Bearer в JS и не скрывать потерю функции.

A03. Android-переход без потери аккаунтов. Зафиксировать package, versionCode выше прежнего и подпись, позволяющие обновить выданный QA APK. Реализовать проверяемую одноразовую миграцию существующего SecureStore: все аккаунты, активный аккаунт, незавершённые команды; без отправки токена/ключей в логи. Если какой-то формат нельзя автоматически перенести, предоставить работающий явный recovery-путь с предупреждением до потери данных. Проверить настоящий install -r старый Kotlin → новый Capacitor с синтетическими данными в том же package/cert. Новый Vault шифруется AndroidKeyStore, backup/logging выключены, сбой/инвалидация ключа приводит к понятному восстановлению, не к белому экрану. Не очищать данные пользовательского приложения для теста; baseline и миграцию испытывать в изолированном тестовом окружении/на синтетическом локальном QA пакете.

A04. Надёжность API v3. Строковые BIGINT cursors/revisions, атомарные delta, snapshot при gap, фильтрация ответов старого аккаунта/generation. Журнал записывается до POST, unknown outcome виден, покупка повторяется только с прежним ключом в безопасный срок, action/leave автоматически и по старому ключу после restart не проигрываются. Защита от двойных нажатий, 409, 401, 429/Retry-After, сервера 5xx и потери ответа после COMMIT. Никаких изменений игрового состояния по клиентским данным.

A05. Lifecycle и нагрузка. Long poll или другой проверенный transport с авторизацией без токена в URL. Частые background/foreground/online/offline не размножают native HTTP-запросы: отмена либо строго ограниченный single-flight с корректным возобновлением. Остановка подписки при logout/смене аккаунта. Системный Back, модальные окна, клавиатура, safe areas и возврат из фона. Нет частого bootstrap/profile polling в простое. Ошибки bootstrap/storage не блокируют recovery UI.

A06. Функции v3 и паритет. Реализовать и проверить режимы play/tutorial, duel, room, team, trial, local; малое и большое поле; короли, все направления, удаление, телепортация source/target, angry; серверные подсказки/результат/история/награды. Инвентарь, кейсы, рынок с фильтром/сортировкой/пагинацией, продажа со скином/отмена/покупка, улучшения/max, рамки, аватары, скины, задания/уровни. Явно добавить удаление аккаунта с подтверждением, жалобы, block/unblock и проверяемый эффект, privacy/support/deletion ссылки. Не показывать fake total рынка или несуществующий instant/promo. Каталог согласован с сервером; несовместимость contentVersion ведёт к понятному обновлению клиента.

A07. Android release. Сборки dev/local и production API разделены; production запрещает cleartext, debug/preview URL и отладочные возможности. Получить QA APK с production-подобными настройками/R8 и корректной подписью, подготовить release APK/AAB при доступных ключах. Проверить manifest, URL, certificate, versionCode, packaged assets и запуск оптимизированной сборки, а не только debug. Проверить native libraries / 16 KB, если они есть. Секреты не коммитить. Store-публикация и production deployment не входят в автоматический выпуск этого задания.

A08. iOS. Подготовить Capacitor iOS проект/адаптер Keychain, lifecycle/config и macOS CI build/check. Не подменять Keychain открытыми Preferences. На Windows нельзя объявить сборку/тест WKWebView выполненными. При отсутствии Mac результат iOS — явно UNVERIFIED с точными командами и внешним условием приёмки; это не должно останавливать законченную Android/web реализацию.

A09. CI/CD и эксплуатация. Воспроизводимые npm ci/build/tests, web E2E с изолированным PostgreSQL, Android build/smoke, проверки секретов/опасного config, macOS iOS job. Готовые конфиги web same-origin hosting для указанного домена, health/readiness, согласованные версии клиента/API, инструкция staged deployment/rollback. Разобрать npm audit: устранить известную цепочку CLI/xcode/uuid или документировать проверенное исключение dev-only с ограничением, не применять слепой audit fix --force. Проверить API v3 server tests после изменений auth/transport.

Критерии приёмки (root повторяет независимо)
K01 = A01: чистая сборка из source без historical dist; одинаковая версия web assets в браузере/APK, реальные снимки основных экранов без существенной потери оригинального UI.
K02 = A02: интеграционные тесты cookie-флагов, отсутствия Bearer в web responses/storage, отказ cross-origin mutation/CSRF, постоянного входа, нескольких аккаунтов, logout/revoke/delete. Native Bearer regression PASS.
K03 = A03: реальный update-install тест Kotlin → Capacitor с совпадающим cert/package и возросшим versionCode; ID/активный аккаунт/инвентарь/баланс и несколько аккаунтов сохранены, журнал unknown не потерян и не исполнен дважды; force-stop/relaunch PASS.
K04 = A04/A05: tests lost-after-COMMIT, duplicate tap, delta gap, 401/409/429, stale response after account switch, repeated pause/resume с измеренным числом запросов, offline/reconnect; нет double mutation/утечки состояния.
K05 = A06: таблица каждого перечисленного сценария с PASS/FAIL/UNVERIFIED и конкретным тестом/скриншотом. Для мутаций проверить сервер/БД; открытие экрана не означает проверку действия. Для сети хотя бы реальный room/duel и 2×2 с событиями других игроков. Для cosmetics/market обязательны покупка/продажа/скин/отмена/пагинация/max.
K06 = A07: manifest/cert/version/API/resources report, подписанный оптимизированный QA APK, установка и функциональный smoke. Реальный телефон и API26/WebView, если недоступны, выделить отдельными внешними gates, не писать PASS.
K07 = A08: проверяемый iOS source/Keychain/config/CI; macOS build/device test PASS только при фактическом выполнении, иначе внешняя приёмка явно остаётся открытой.
K08 = A09: local equivalent CI commands PASS, server regression PASS, подготовленные deploy/rollback инструкции; CI workflow не считать успешно выполненным в GitHub, если он только написан.
K09: документация, release manifest с SHA-256, список файлов/сборок/команд, ограничения и оставшиеся внешние действия. Нет секретов в tracked files, screenshots, logs/reports; нет изменений/тестовых записей на production.

Работать автономно в разрешённой области, исправлять найденные дефекты. Не спрашивать повторное разрешение на локальную разработку/тесты. Сообщать root о существенных находках и готовности отдельных критериев. Реально недоступные внешние проверки не скрывать под общим «готово».
