# «Символы»: исходники опубликованной версии 45

Экспорт оригинального коммита `453f22d1cef29bf771fb61906354600aae8179b3`, действовавшего 6 октября 2026 года:
https://simvoly-game.votarumshee.chatgpt.site/

Это исходный многофайловый проект, а не реконструкция публичной страницы.
76 файлов исходного коммита доступны; изображения включены. Серверные сборочные
файлы `server/assets.mjs` и `dist/server/index.js` генерируются командой сборки.
Исходные настройки Sites сохранены в `.openai/hosting.json`; **не используйте
этот project_id для публикации своей копии**.

## Быстрый локальный запуск

Нужны Node.js 24 (проверено 24.19.0), npm; Python 3 нужен только для повторной генерации SQL.

```sh
npm ci
npm run build
node scripts/init-db.mjs data/symbols.sqlite
node scripts/local-server.mjs
```

Открыть http://127.0.0.1:8787 . База создаётся локально, рабочий сайт не затрагивается.
Процесс останавливается Ctrl+C. После перезапуска данные сохраняются в SQLite.
Для настроек скопируйте `.env.example` в `.env`, затем:
`node --env-file=.env scripts/local-server.mjs`.
Токены GitHub для запуска игры не требуются.

- `dist/*.mjs, *.css, index.html, *.png` — исходный клиент и ресурсы.
  Несмотря на имя dist, эти файлы — редактируемые оригинальные исходники.

  восстановление аккаунтов, прежнее API.

- `db/schema.ts`, `drizzle/` — оригинальная схема Drizzle и 6 миграций.
- `scripts/` — **добавлено при экспорте**: локальный Node-хост, создание тестовой БД,

- `docs/source-manifest.json` — SHA-256 всех 76 файлов исходного коммита.

Исторические RULES.md, старые клиентские модули и тесты сохранены как оригиналы.

index.html → next.mjs → /api/v2 → server/v2.mjs.

## Реальное хранение данных

Рабочая игра использует Cloudflare D1 (SQLite-совместимая управляемая БД),
привязка `DB`. Точная версия SQLite в рабочем D1 недоступна по имеющимся
метаданным и не проверялась запросами к рабочей БД.
В локальных тестах Node SQLite — 3.53.3.
Основные данные находятся в 9 таблицах, часть сложных объектов — JSON в TEXT:
инвентарь, выбранные скины, их владение, баланс, улучшения и состояние матча.

localStorage хранит реестр аккаунтов, токены сессий и клиентский кеш/прежний прогресс.
IndexedDB в исходном коде не используется.
R2 `AVATARS` нужен только для чтения прежних пользовательских JPG; загрузка
пользовательских аватарок отключена. Современные аватарки — включённые PNG/emoji.
Сторонних API, обязательных ключей или внешнего сервера ИИ у игры нет.
Покупки производятся за игровые рубины; платёжный шлюз отсутствует.

## Наполнение и личные данные

Исходно справочники не хранились в SQL: они заданы в JS.
`database/content.json` — воспроизводимый снимок констант:
символы, редкости, уровни 1–300, задания (актуальные и отдельно legacy),
кейсы и веса выпадения, рамки, скины, допустимые пары символ/скин,
аватарки/наборы, звания, сложности, ступени улучшений и настройки.

`game_content` и `game_content_links` — **новые экспортные справочные таблицы**,
одинаковые во всех трёх вариантах. Приложение продолжает читать константы из JS,
а не из этих таблиц. Формулы уровней после 300, логика заданий, подсказок и боя
сохранены в коде; контентный SQL не заменяет исполняемые правила.

Игроки, личные никнеймы, истории матчей, текущие предложения, токены, хеши
сессий/восстановления, production R2 и дампы рабочей БД исключены.
В тестах создаются только синтетические записи в отдельных временных БД.
Полное восстановление накопленного мира без приватной резервной копии невозможно.

Пересобрать справочники и SQL:
```sh
node scripts/export-content.mjs
python3 scripts/generate-sql.py
```

## Запуск вне Sites

Добавленный Node-хост на SQLite позволяет запустить игру без Sites/Cloudflare.
Это тонкий адаптер D1 `prepare/bind/first/all/run/batch`; оригинальное игровое API
не переписано. Транзакции batch выполняются атомарно. Локальный хост предназначен
для разработки, не является готовой защищённой production-платформой:
для публичного запуска нужны HTTPS, ограничения запросов, мониторинг,
резервные копии, защита токенов, настройка reverse proxy и проверка нагрузки.
HTTP origin/proxy должны быть согласованы; клиент использует относительный /api.
Не используйте простую раздачу dist как замену игровому серверу.

Для Cloudflare Workers отдельно создайте собственные D1/R2 и конфигурацию
Wrangler с entrypoint server/worker.mjs, привязкой D1 DB и при необходимости R2
AVATARS. Сначала npm run build; миграции drizzle применяйте только к своей БД.
Служебный проект Sites и его БД при экспорте не изменялись.
Старые личные изображения R2 в локальной копии дадут 404 — это намеренное исключение.

## PostgreSQL и Microsoft SQL Server

**Код игры напрямую с ними не работает.** SQL-комплекты отражают схему и
справочники, но драйверов/адаптеров этих СУБД в оригинале нет.

Нужно реализовать аналог DB и переписать SQLite-специфичные места:
параметры ?, INSERT OR IGNORE/ON CONFLICT, RETURNING/OUTPUT, json_extract,
randomblob/hex, рекурсивную генерацию предложений, PRAGMA и миграции.
Важно сохранить атомарность операций, проверку revision и защиту от повторного
покупания/начисления. В SQL Server CTE для массовой продажи также требует
учёта MAXRECURSION. Сверьте типы цен и JSON; описание — database/README.md.
Масштабный порт приложения не входит в экспорт.
