# API v3 — Kotlin handoff

The authoritative machine-readable contract is `openapi.yaml` (JSON syntax, valid YAML 1.2); event frames use `events.schema.json`. Generate with `node Server/scripts/contracts.mjs`; CI checks consistency. The exact tested Server commit for Client is recorded in `server-version.json`: `f9f8dede3d2d035d055e313a760e1262ceec39db`. Pin it in Client's dependency manifest. No public v2 adapter is exposed: the published web game remains on the export branch.

HTTP JSON commands are the only write transport. Bearer session tokens must remain in Android encrypted storage and never appear in URLs. HTTPS and WSS terminate at Caddy. Tokens expire after 30 days; recovery revokes previous sessions. A recovery code can be legacy nine decimal digits (SHA-256 compatibility) or a new 128-bit hexadecimal code. Issuing a code never accepts localStorage progress. Recovery-code response is shown once; retrying its idempotency key returns `code:null, regenerate:true`, because plaintext recovery secrets are not stored in command receipts. Request a new key to replace a lost code.

IDs are opaque strings, including old non-UUID IDs. BIGINT revisions/cursors and money are decimal strings over the wire. Kotlin uses Long after range checks (money max 9007199254740991 cents). Internal JS calculations use checked safe integers; `balance` is only a legacy display cache. `sell.price` is a decimal string in rubies with up to two fractional digits; the 90% skin surcharge is calculated by the server. UTC epoch milliseconds are used in gameplay/history; ISO-8601 UTC strings for serverTime, session/database timestamps. Queue 8s, bot 450ms, turn expires strictly after 90s. Sizes are [height,width].

Bootstrap returns one REPEATABLE READ snapshot of profile, active match, revision and user cursor. Open WSS with that cursor; the server attaches notification listener before reading durable history. Events between snapshot and subscription are replayed. Each user has a separate transactional cursor, so uncommitted events cannot be skipped by sequence-number commit inversion. Apply only events with a cursor greater than the stored cursor; duplicates are safe to ignore. If the next cursor is not current+1, or match baseRevision mismatches, fetch a fresh bootstrap. A match snapshot replaces the current match; otherwise apply top-level patch fields and `board.cells` by side/index. Null clears a field. `profilePatch` replaces each supplied top-level field; absent fields stay unchanged. Profile `revision` tracks the owner's event revision; match revision is independent. The immutable game board is public in v45; inventories and match stocks of other users remain private. No random seed is sent.

History retention: 24 hours, cleanup every minute; active owners are additionally bounded to 10000 events. A cursor below the retained floor returns 409 SNAPSHOT_REQUIRED. Close/reconnect uses the last applied cursor. On service restart NOTIFY is only a wakeup optimization: persisted events are authoritative. A 20-second WS heartbeat rechecks authorization and missed notifications without profile writes. Client sends pong only; sending commands over WS closes it. A maximum of three connections per account per process and 1000 total per process applies. Long polling `/changes` waits up to 25 seconds and returns the same pages of at most 100 events.

Economic/game command results persist for seven days, scoped by user/key plus kind and canonical parameter hash. Retrying the same command returns its receipt without repeating the effect. Reusing a key with changed parameters returns 409 IDEMPOTENCY_CONFLICT. Client must generate a new key for a genuinely new action, store pending commands, and must not blindly resubmit after seven days. Stale match revision returns 409 REVISION_CONFLICT. Receipt responses do not carry entire profiles/boards; consume events or bootstrap. Deletion/logout revoke authorization; subsequent retries may return 401, which is expected after success.

Errors: 400 invalid request/rule, 401 missing/expired/revoked credentials, 403 ownership or blocked interaction, 404 absent resource, 409 revision/receipt/resync conflict, 413 body >16 KiB, 429 throttling with Retry-After seconds, 503 transient database failure. Never display stack traces. Registration: 10 per IP/15min; recovery: 5 per IP/15min; commands: 120 per account/min; report/code generation: 5/15min; WS handshakes: 30/min; long poll: 60/min. Deployment must set trusted proxy networks explicitly.

Blocking prevents new matchmaking/room joins and market purchases between the pair. It does not cancel an already running game. Reports are reviewed with the private admin CLI. Delete-account requires current authentication and explicit confirm; shared games are removed without new rewards, open listings are cancelled, own private records/credentials removed, opponents resynchronize. Backups expire separately according to the operator's declared retention policy.

Content is versioned by SHA-256 of the canonical catalog. Cache catalog by version and ETag. Server uses these same records for symbols, prices, cases, ranks and upgrade costs; executable combat/progression formulas remain code. Levels above 300 continue by the versioned formula. No enabled promos or arbitrary avatar uploads exist in v3.

The Kotlin branch adds optional, backward-compatible public projections: `profile.level` contains authoritative level/xp/start/next/frame (including levels above 300), `match.advice` contains the original tutorial recommendation for its owner, and `match.effects` contains allowlisted completed projectile paths and impacts. These additions require the Server from this branch; the pinned earlier Server remains the contract baseline. Existing clients may ignore them. No balance, command semantics or private opponent inventory changed.
